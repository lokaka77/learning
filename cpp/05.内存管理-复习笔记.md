## 1. C/C++内存分布

int globalVar = 1;

### 1.1 五个内存区域

原课件给出的说明：

1. **栈**又叫堆栈。非静态局部变量、函数参数、返回值等等都放在这里，栈是向下增长的。
2. **内存映射段**是高效的 I/O 映射方式，用于装载一个共享的动态内存库。用户可使用系统接口创建共享内存，做进程间通信。（Linux 课程如果没学到这块，现在只需要了解一下）
3. **堆**用于程序运行时动态内存分配，堆是可以向上增长的。
4. **数据段**存储全局数据和静态数据。
5. **代码段**存放可执行的代码和只读常量。

补充说明：

- 这里的"增长方向"指地址的增长方向。栈从高地址向低地址扩展，堆从低地址向高地址扩展，两者相向生长，这样可以尽量充分利用中间的空闲地址空间。
- 32 位 Linux 下典型的地址划分是：内核空间占最高的 1GB（用户代码不能读写），往下依次是栈、内存映射段、堆、未初始化数据段（BSS）、已初始化数据段、代码段。
- 数据段实际分两块：已初始化的全局/静态变量放在 `.data`，未初始化（或初始化为 0）的放在 `.bss`，两者都可以归到"数据段（静态区）"这个考点里。
- 字符串字面量 `"abcd"` 是只读常量，属于代码段（常量区），`*pChar3` 落在这一块；而 `char2` 是数组，字面量的内容被**拷贝**到了栈上，所以 `*char2` 在栈上。

### 1.2 选择题答案与解析

| 表达式 | 所在区域 | 解析 |
| --- | --- | --- |
| `globalVar` | 数据段（静态区） | 全局变量 |
| `staticGlobalVar` | 数据段（静态区） | 静态全局变量，链接属性不同，但存储位置同样是静态区 |
| `staticVar` | 数据段（静态区） | 静态局部变量，虽然定义在函数里，但不随函数结束销毁 |
| `localVar` | 栈 | 非静态局部变量 |
| `num1` | 栈 | 局部数组，整个数组本体在栈上 |
| `char2` | 栈 | 数组本体在栈上 |
| `*char2` | 栈 | `char2` 是把 `"abcd"` 拷贝到栈数组里，`*char2` 即 `char2[0]`，在栈上 |
| `pChar3` | 栈 | 指针变量本身是局部变量 |
| `*pChar3` | 代码段（常量区） | 指针指向字符串字面量 `"abcd"`，字面量在只读常量区 |
| `ptr1` | 栈 | 指针变量本身是局部变量 |
| `*ptr1` | 堆 | `malloc` 申请的 16 字节空间在堆上 |

**易错点**：

1. 分清"变量本身"和"变量指向的空间"。`ptr1` 在栈上，`*ptr1` 在堆上，这是本题最常考的一对吧。
2. `char2` 与 `pChar3` 要对比记忆：数组是拷贝一份内容到栈，指针只是指向常量区的字面量。所以 `*char2` 在栈，`*pChar3` 在常量区。
3. 数组名代表整个数组，不能说"数组名在栈、数组元素在堆"；`num1[0]`、`num1[9]` 全部都在栈上。
4. 静态局部变量 `staticVar` 的"出生地"在函数里，但"住址"在静态区，函数结束不会被回收，这也是它可以跨调用保持值的原因。

## 2. C语言中动态内存管理方式：malloc/calloc/realloc/free

```cpp
void Test ()
{
    // 1.malloc/calloc/realloc的区别是什么？
    int* p2 = (int*)calloc(4, sizeof (int));
    int* p3 = (int*)realloc(p2, sizeof(int)*10);

    // 这里需要free(p2)吗？
    free(p3 );
}
```

**【面试题】**

1. malloc/calloc/realloc的区别？
2. malloc的实现原理？ glibc中malloc实现原理

### 2.1 面试题讲解：malloc/calloc/realloc 的区别

| 函数 | 功能 | 参数 | 是否初始化 | 返回值 |
| --- | --- | --- | --- | --- |
| `malloc(size)` | 申请 `size` 字节的连续空间 | 一个总字节数 | 不初始化，内容是随机的 | 成功返回 `void*`，失败返回 `NULL` |
| `calloc(n, size)` | 申请 `n` 个、每个 `size` 字节的空间 | 元素个数 + 单个元素大小 | 全部初始化为 0 | 成功返回 `void*`，失败返回 `NULL` |
| `realloc(ptr, size)` | 调整 `ptr` 指向空间的大小 | 原指针 + 新字节数 | 新增部分不初始化 | 成功返回新地址，失败返回 `NULL`（原块不变） |
| `free(ptr)` | 释放动态申请的空间 | 指针 | —— | 无返回；`free(NULL)` 是安全的 |

补充要点：

1. `calloc` 会清零，`malloc` 不会，这是两者最直接的区别；`calloc` 还会检查 `n * size` 是否溢出。
2. `realloc` 的两种行为：如果原块后面空间够，就原地扩大并返回原地址；如果不够，就另找一块新空间，把原内容拷贝过去，释放旧块，返回新地址。所以**旧指针在新块搬迁后就不能再用了**。
3. `realloc` 失败返回 `NULL` 时，原块仍然有效，因此不要写 `p = realloc(p, n)`，一旦失败就连原指针都丢了，正确写法是：

```cpp
int* tmp = (int*)realloc(p, sizeof(int) * 10);
if (tmp == NULL)
{
    // 处理失败，p 仍然有效
}
else
{
    p = tmp;
}
```

4. 申请的内存不会再被自动回收，必须 `free`，否则就是内存泄漏；`free` 之后指针最好置 `NULL`，避免悬空指针被重复释放。

### 2.2 面试题讲解：这里需要 free(p2) 吗？

**不需要，而且不应该 free(p2)**。`realloc(p2, ...)` 之后，`p2` 指向的旧空间可能已经被扩展、搬迁甚至释放；此时再 `free(p2)` 属于对悬空指针的重复释放，是未定义行为（可能崩溃、可能破坏堆结构）。正确做法是只 `free(p3)`。

如果确实还想保留 `p2` 这个变量名，就要像上面那样用临时指针接收 `realloc` 的返回值，再把 `p2` 更新为新地址，之后只释放一次。

### 2.3 面试题讲解：malloc 的实现原理（glibc 简述）

以 glibc 的 `ptmalloc2` 为例，回答时抓住下面几点即可：

1. `malloc` 申请的内存并不是"裸内存"：每块内存前面有 chunk 头（记录大小、使用状态、前后块信息等），返回给用户的是 chunk 头之后的部分，所以实际占用的内存比申请的字节数要多。
2. 空闲的 chunk 按大小分类挂进不同的 bins（fastbins、smallbins、largebins、unsorted bin），下次申请相近大小时直接复用，避免频繁向系统要内存。
3. 申请较小的空间时，通过 `brk` 移动堆顶指针来扩展堆；申请较大的空间（默认阈值 128KB，可用 `mallopt` 调整）时改用 `mmap` 单独映射一段，用完直接归还给系统。
4. 分配地址按 16 字节对齐（32 位平台通常是 8 或 16 字节），所以 `malloc(1)` 实际会占用一个对齐后的 chunk。
5. glibc 2.26 之后加入了 tcache（每线程缓存），小内存释放后先进线程本地缓存，再次申请时命中更快。

## 3. C++内存管理方式

C语言内存管理方式在C++中可以继续使用，但有些地方就无能为力，而且使用起来比较麻烦，因此C++又提出了自己的内存管理方式：**通过new和delete操作符进行动态内存管理**。

### 3.1 new/delete操作内置类型

```cpp
void Test()
{
    // 动态申请一个int类型的空间
    int* ptr4 = new int;

    // 动态申请一个int类型的空间并初始化为10
    int* ptr5 = new int(10);

    // 动态申请10个int类型的空间
    int* ptr6 = new int[3];

    delete ptr4;
    delete ptr5;
    delete[] ptr6;
}
```

![new/delete操作内置类型图解：new后跟类型，类型后可加初始化值，[]中指定对象个数，delete和delete[]配对使用](<../课件/C++初阶新版课件+(1)/assets/05/page3_img1.png>)

**注意：申请和释放单个元素的空间，使用new和delete操作符，申请和释放连续的空间，使用new[]和delete[]，注意：匹配起来使用。**

补充说明：

1. `new int` 只申请 4 字节，不初始化；`new int(10)` 初始化为 10；`new int[3]` 申请 3 个 int，内置类型同样**不初始化**。
2. C++11 起可以写 `new int[3]()` 把数组值初始化为 0，圆括号不能少。
3. `delete` 与 `new` 配对、`delete[]` 与 `new[]` 配对，四种组合不能交叉。对内置类型混用有时"看着没事"，但依然是未定义行为；对自定义类型混用基本必现问题（见 5.2 节）。
4. `new` 申请失败时抛 `std::bad_alloc` 异常，而不是返回 `NULL`。

### 3.2 new和delete操作自定义类型

```cpp
class A
{
public:
    A(int a = 0)
        : _a(a)
    {
        cout << "A():" << this << endl;
    }
    ~A()
    {
        cout << "~A():" << this << endl;
    }
private:
    int _a;
};

int main()
{
    // new/delete 和 malloc/free最大区别是 new/delete对于【自定义类型】除了开空间还会调用构造函数和析构函数
    A* p1 = (A*)malloc(sizeof(A));
    A* p2 = new A(1);
    free(p1);
    delete p2;
    // 内置类型是几乎是一样的
    int* p3 = (int*)malloc(sizeof(int)); // C
    int* p4 = new int;
    free(p3);
    delete p4;
    A* p5 = (A*)malloc(sizeof(A)*10);
    A* p6 = new A[10];
    free(p5);
    delete[] p6;
    return 0;
}
```

**注意：在申请自定义类型的空间时，new会调用构造函数，delete会调用析构函数，而malloc与free不会。**

补充说明：

1. `A* p2 = new A(1)` 做了两件事：先申请 `sizeof(A)` 字节，再在这块空间上调用构造函数。
2. `delete p2` 的顺序相反：先调用析构函数清理对象内部资源，再释放空间。
3. `new A[10]` 会调用 10 次构造函数，`delete[] p6` 会调用 10 次析构函数；构造按顺序、析构逆序，可以通过打印验证。
4. `malloc/free` 得到的空间里根本没有"对象"，所以既不会调用构造也不会调用析构。如果 `A` 内部持有资源（比如 `char* _str`），`free(p1)` 会直接泄漏 `_str` 指向的空间，这也是必须把 `malloc/free` 和 `new/delete` 分开配对的原因。

## 4. operator new与operator delete函数（重要点进行讲解）

### 4.1 operator new与operator delete函数（重点）

**new和delete**是用户进行**动态内存申请和释放的操作符**，**operator new 和operator delete**是系统提供的**全局函数**，**new在底层调用operator  new**全局函数来申请空间，**delete在底层通过operator delete**全局函数来释放空间。

```cpp
/*
operator new：该函数实际通过malloc来申请空间，当malloc申请空间成功时直接返回；申请空间
失败，尝试执行空间不足应对措施，如果该应对措施用户设置了，则继续申请，否则抛异常。
*/
void *__CRTDECL operator new(size_t size) _THROW1(_STD bad_alloc)
{
    // try to allocate size bytes
    void *p;
    while ((p = malloc(size)) == 0)
        if (_callnewh(size) == 0)
        {
            // report no memory
            // 如果申请内存失败了，这里会抛出bad_alloc 类型异常
            static const std::bad_alloc nomem;
            _RAISE(nomem);
        }
    return (p);
}
/*
operator delete: 该函数最终是通过free来释放空间的
*/
void operator delete(void *pUserData)
{
    _CrtMemBlockHeader * pHead;
    RTCCALLBACK(_RTC_Free_hook, (pUserData, 0));
    if (pUserData == NULL)
        return;
    _mlock(_HEAP_LOCK);  /* block other threads */
    __TRY
        /* get a pointer to memory block header */
        pHead = pHdr(pUserData);
         /* verify block type */
        _ASSERTE(_BLOCK_TYPE_IS_VALID(pHead->nBlockUse));
        _free_dbg( pUserData, pHead->nBlockUse );
    __FINALLY
        _munlock(_HEAP_LOCK);  /* release other threads */
    __END_TRY_FINALLY
    return;
}
/*
free的实现
*/
#define   free(p)               _free_dbg(p, _NORMAL_BLOCK)
```

通过上述两个全局函数的实现知道，**operator new 实际也是通过malloc来申请空间**，如果malloc申请空间成功就直接返回，否则执行用户提供的空间不足应对措施，如果用户提供该措施就继续申请，否则就抛异常。**operator delete 最终是通过free来释放空间的**。

补充说明：

1. `new` 的执行路径是：`new` → `operator new(size)` → `malloc`；失败时进入 new_handler 循环（上面代码里的 `_callnewh` 就是对应机制，可用 `std::set_new_handler` 设置自己的应对措施）。
2. `delete` 的执行路径是：先调用析构函数，再 `operator delete(ptr)` → `free`。所以 `new/delete` 比 `malloc/free` "高级"的地方就是构造/析构和异常处理，而底层的空间来源其实一样。
3. `operator new` 和 `operator delete` 是**全局函数**，也可以被类自己重载，或者在全局范围替换，用来做内存池、内存统计、定位泄漏。重载时必须成对提供，签名形如 `void* operator new(size_t size)` 和 `void operator delete(void* p)`。
4. 申请失败的区别要记牢：`malloc` 返回 `NULL`（要判断），`new` 抛 `std::bad_alloc`（要捕获）；想统一成"返回空指针"可以写 `new (std::nothrow) A`。

## 5. new和delete的实现原理

### 5.1 内置类型

如果申请的是内置类型的空间，new和malloc，delete和free基本类似，不同的地方是：new/delete申请和释放的是单个元素的空间，new[]和delete[]申请的是连续空间，而且new在申请空间失败时会抛异常，malloc会返回NULL。

补充说明：

1. 内置类型没有构造函数和析构函数，所以对它们来说 `new/delete` 只是"换了写法的 malloc/free"：能自动算大小、不用强转、失败时抛异常。
2. 正是因为内置类型"看着一样"，很多人在混用 `new[]` 和 `delete` 时觉得没出问题；但这是未定义行为，只是恰好没暴露，不能依赖。

### 5.2 自定义类型

**new的原理**

1. 调用operator new函数申请空间
2. 在申请的空间上执行构造函数，完成对象的构造

**delete的原理**

1. 在空间上执行析构函数，完成对象中资源的清理工作
2. 调用operator delete函数释放对象的空间

**new T[N]的原理**

1. 调用operator new[]函数，在operator new[]中实际调用operator new函数完成N个对象空间的申请
2. 在申请的空间上执行N次构造函数

**delete[]的原理**

1. 在释放的对象空间上执行N次析构函数，完成N个对象中资源的清理
2. 调用operator delete[]释放空间，实际在operator delete[]中调用operator delete来释放空间

补充说明：

1. `delete[]` 怎么知道 N 是几？对于有析构函数的类型，编译器通常会在申请空间的头部额外多开几个字节把 N 存起来（这就是 `new[]` 有时比 `N * sizeof(T)` 多要一点内存的原因），`delete[]` 读出来后再决定析构多少次。
2. 这也解释了为什么 `new[]` 配 `delete` 会出问题：`delete` 只按单个对象处理，既不会读出正确的 N，也可能把指针偏移算错，结果是析构次数不对、堆结构被破坏。
3. 反过来，`new` 配 `delete[]` 同样是未定义行为，不要尝试。

## 6. 定位new表达式(placement-new) （了解）

定位new表达式是在**已分配的原始内存空间中调用构造函数初始化一个对象**。

**使用格式：**

**new (place_address) type**或者**new (place_address) type(initializer-list)**

**place_address必须是一个指针，initializer-list是类型的初始化列表**

**使用场景：**

定位new表达式在实际中一般是配合内存池使用。因为内存池分配出的内存没有初始化，所以如果是自定义类型的对象，需要使用new的定位表达式显式调用构造函数进行初始化。

```cpp
class A
{
public:
    A(int a = 0)
        : _a(a)
    {
        cout << "A():" << this << endl;
    }
    ~A()
    {
        cout << "~A():" << this << endl;
    }
private:
    int _a;
};
// 定位new/replacement new
int main()
{
    // p1现在指向的只不过是与A对象相同大小的一段空间，还不能算是一个对象，因为构造函数没有执行
    A* p1 = (A*)malloc(sizeof(A));
    new(p1)A;  // 注意：如果A类的构造函数有参数时，此处需要传参
    p1->~A();
    free(p1);
    A* p2 = (A*)operator new(sizeof(A));
    new(p2)A(10);
    p2->~A();
    operator delete(p2);
    return 0;
}
```

补充说明：

1. 定位 new 只负责"在指定地址上调用构造函数"，**不申请内存**，所以地址必须自己准备好（可以是 `malloc` 的空间、`operator new` 的空间，也可以是栈上的缓冲区）。
2. 构造和析构要配对：用定位 new 构造出来的对象，必须显式调用析构函数 `p->~A()`；释放原始空间时要用当初申请的方式（`malloc` 配 `free`，`operator new` 配 `operator delete`）。
3. **不要对定位 new 的对象直接 `delete`**：`delete` 会调用全局 `operator delete` 去释放一块并不是由 `operator new` 申请的内存，配对错误就是未定义行为。
4. 标准库的定位 new 声明在 `<new>` 头文件里；标准库容器分配器（`allocator`）把"申请空间"和"构造对象"分开，用的就是这一思路。
5. 顺便对比：`new(p1)A` 里 `new` 后面的 `(p1)` 是"放置地址"，和 `new int(10)` 里表示初始化的圆括号位置和含义都不同，不要混淆。

## 7. malloc/free和new/delete的区别

malloc/free和new/delete的共同点是：都是从堆上申请空间，并且需要用户手动释放。不同的地方是：

1. malloc和free是函数，new和delete是操作符
2. malloc申请的空间不会初始化，new可以初始化
3. malloc申请空间时，需要手动计算空间大小并传递，new只需在其后跟上空间的类型即可，如果是多个对象，[]中指定对象个数即可
4. malloc的返回值为void*, 在使用时必须强转，new不需要，因为new后跟的是空间的类型
5. malloc申请空间失败时，返回的是NULL，因此使用时必须判空，new不需要，但是new需要捕获异常
6. 申请自定义类型对象时，malloc/free只会开辟空间，不会调用构造函数与析构函数，而new在申请空间后会调用构造函数完成对象的初始化，delete在释放空间前会调用析构函数完成空间中资源的清理释放

整理成表格：

| 维度 | malloc/free | new/delete |
| --- | --- | --- |
| 本质 | 函数（`<stdlib.h>`/`<cstdlib>`） | 操作符（关键字），配合 `<new>` 取异常类型 |
| 大小 | 手动算字节数 | 只写类型或对象个数 |
| 类型 | 返回 `void*`，需要强转 | 返回对应类型指针，不需要强转 |
| 初始化 | 不初始化（`calloc` 除外） | 可初始化：`new int(10)`、`new int[3]()` |
| 失败处理 | 返回 `NULL`，必须判空 | 抛 `std::bad_alloc`，需要捕获 |
| 自定义类型 | 只开空间，不构造不析构 | 申请后构造，释放前析构 |
| 底层关系 | —— | `new` → `operator new` → `malloc`；`delete` → `operator delete` → `free` |
| 配对规则 | `free` 配 `malloc/calloc/realloc` | `delete` 配 `new`，`delete[]` 配 `new[]`，两组不能交叉 |

使用建议：

1. C++ 代码优先用 `new/delete`，尤其是自定义类型；和 C 代码、第三方 C 库交互时用 `malloc/free`，两边不要交叉释放。
2. 能用智能指针、容器就不要手写裸 `new`，把释放交给析构函数；本节练习阶段先手动配对，把原理吃透。
3. 高频易错点：`new[]/delete` 混用、用 `free` 释放 `new` 的空间、用 `delete` 释放 `malloc` 的空间、重复释放、只申请不释放导致内存泄漏。

### 7.1 本章补充例题

#### [补充例题·力扣] 208. 实现 Trie（前缀树）

出处：[LeetCode 208. 实现 Trie（前缀树）](https://leetcode.cn/problems/implement-trie-prefix-tree/)

题目：实现前缀树 `Trie`，支持 `insert`（插入单词）、`search`（查询单词是否存在）、`startsWith`（查询是否有单词以某前缀开头）。

为什么放在本章：每个节点都用 `new` 动态申请，析构时又要递归 `delete` 全部节点，正好练习"new 出来的空间由谁释放、树形结构怎么递归释放"。

```cpp
#include <string>
using namespace std;

class Trie {
public:
    Trie() : _root(new Node()) {}

    ~Trie()
    {
        destroy(_root);
        _root = nullptr;
    }

    void insert(string word)
    {
        Node* cur = _root;
        for (size_t i = 0; i < word.size(); ++i)
        {
            int idx = word[i] - 'a';
            if (cur->_next[idx] == nullptr)
            {
                cur->_next[idx] = new Node();
            }
            cur = cur->_next[idx];
        }
        cur->_isEnd = true;
    }

    bool search(string word)
    {
        Node* cur = find(word);
        return cur != nullptr && cur->_isEnd;
    }

    bool startsWith(string prefix)
    {
        return find(prefix) != nullptr;
    }

private:
    struct Node
    {
        bool _isEnd;
        Node* _next[26];

        Node() : _isEnd(false)
        {
            for (int i = 0; i < 26; ++i)
            {
                _next[i] = nullptr;
            }
        }
    };

    Node* _root;

    Node* find(const string& s)
    {
        Node* cur = _root;
        for (size_t i = 0; i < s.size(); ++i)
        {
            int idx = s[i] - 'a';
            if (cur->_next[idx] == nullptr)
            {
                return nullptr;
            }
            cur = cur->_next[idx];
        }
        return cur;
    }

    static void destroy(Node* p)
    {
        if (p == nullptr)
        {
            return;
        }
        for (int i = 0; i < 26; ++i)
        {
            destroy(p->_next[i]);
        }
        delete p;
    }
};
```

复杂度：

- 时间复杂度：`insert`、`search`、`startsWith` 均为 `O(L)`，`L` 为字符串长度
- 空间复杂度：`O(N)`，`N` 为节点总数（每个节点固定 26 个指针）

**讲解**：

1. 每个 `Node` 用 26 个指针表示 `a` 到 `z` 的子节点，`_isEnd` 标记"从根到该节点是否构成一个完整单词"。
2. `search` 与 `startsWith` 只差一个判断：前者要求找到的节点 `_isEnd == true`，后者只要路径存在即可。
3. 构造时 `new Node()`，析构时用 `destroy` 递归释放整棵树，`delete` 与 `new` 一一配对；力扣判题不会检查内存泄漏，但工程代码里这类"树形结构手动释放"必须写对，否则整个 Trie 都是泄漏的。
4. 边界：空字符串调用 `search("")` 返回 `false`、`startsWith("")` 返回 `true`（根节点存在），注意题目是否允许空串。

#### [补充例题·牛客] 设计LRU缓存结构

出处：[牛客 BM100 设计LRU缓存结构](https://www.nowcoder.com/practice/e3769a5f49894d49b871c09cadd13a61)

题目：设计 LRU（最近最少使用）缓存结构，支持 `put(key, value)` 和 `get(key)`：`get` 命中返回对应的 value，否则返回 `-1`；容量满时，写入新数据前淘汰最久未使用的数据。牛客的输入是二维数组 `operators`（`{1, key, value}` 表示 put，`{2, key}` 表示 get）和容量 `k`，返回每次 get 的结果数组。

为什么放在本章：链表节点全部用 `new` 申请，淘汰时要及时 `delete`，还要在构造、析构、复用同一个对象时都保证不泄漏，是"动手管理内存"的典型练习。

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    Solution() : _head(new Node(0, 0)), _tail(new Node(0, 0)), _capacity(0)
    {
        _head->_next = _tail;
        _tail->_prev = _head;
    }

    ~Solution()
    {
        clear();
        delete _head;
        delete _tail;
        _head = nullptr;
        _tail = nullptr;
    }

    vector<int> LRU(vector<vector<int> >& operators, int k)
    {
        clear();
        _capacity = k;
        vector<int> ret;
        for (size_t i = 0; i < operators.size(); ++i)
        {
            const vector<int>& op = operators[i];
            if (op[0] == 1)
            {
                setValue(op[1], op[2]);
            }
            else
            {
                ret.push_back(getValue(op[1]));
            }
        }
        return ret;
    }

private:
    struct Node
    {
        int _key;
        int _value;
        Node* _prev;
        Node* _next;

        Node(int key, int value)
            : _key(key)
            , _value(value)
            , _prev(nullptr)
            , _next(nullptr)
        {}
    };

    Node* _head;
    Node* _tail;
    int _capacity;
    unordered_map<int, Node*> _map;

    void clear()
    {
        Node* cur = _head->_next;
        while (cur != _tail)
        {
            Node* next = cur->_next;
            delete cur;
            cur = next;
        }
        _head->_next = _tail;
        _tail->_prev = _head;
        _map.clear();
    }

    void addToHead(Node* node)
    {
        node->_prev = _head;
        node->_next = _head->_next;
        _head->_next->_prev = node;
        _head->_next = node;
    }

    void removeNode(Node* node)
    {
        node->_prev->_next = node->_next;
        node->_next->_prev = node->_prev;
    }

    void moveToHead(Node* node)
    {
        removeNode(node);
        addToHead(node);
    }

    void setValue(int key, int value)
    {
        if (_capacity <= 0)
        {
            return;
        }
        unordered_map<int, Node*>::iterator it = _map.find(key);
        if (it != _map.end())
        {
            it->second->_value = value;
            moveToHead(it->second);
            return;
        }
        Node* node = new Node(key, value);
        _map[key] = node;
        addToHead(node);
        if ((int)_map.size() > _capacity)
        {
            Node* last = _tail->_prev;
            _map.erase(last->_key);
            removeNode(last);
            delete last;
        }
    }

    int getValue(int key)
    {
        unordered_map<int, Node*>::iterator it = _map.find(key);
        if (it == _map.end())
        {
            return -1;
        }
        moveToHead(it->second);
        return it->second->_value;
    }
};
```

复杂度：

- 时间复杂度：每次 `put`/`get` 平均 `O(1)`
- 空间复杂度：`O(k)`，`k` 为缓存容量

**讲解**：

1. 经典结构是"哈希表 + 双向链表"：哈希表负责 `O(1)` 定位节点，双向链表维护使用顺序，头部是最近使用、尾部是最久未使用。
2. 两个哨兵节点 `_head`、`_tail` 让插入和删除都不用判空，`removeNode`/`addToHead` 可以少写一堆边界判断。
3. 内存管理是本题的重点：`put` 新键时 `new Node`，容量满时从尾部摘掉节点并 `delete`；`LRU` 每次调用先 `clear()`，析构函数里再统一释放，保证重复调用和对象销毁都不会泄漏。
4. 细节：`put` 已存在的 key 要更新 value 并把自己移到头部；`get` 命中也要移到头部；`get` 未命中返回 `-1`；容量 `k` 不大于 0 时 `put` 直接忽略。
5. 用 `std::list` 也能写，但为了练本章的 `new/delete`，这里手写了双向链表；换成 `list` 时"节点释放"由容器负责，可以用来自查你对两种写法的理解是否一致。

### 7.3 本章复习速查

| 主题 | 核心结论 |
| --- | --- |
| 内存区域 | 内核空间、栈、内存映射段、堆、数据段、代码段 |
| 增长方向 | 栈向下增长，堆向上增长 |
| 变量判断 | 先分清"变量本身"和"变量指向的空间"；数组本体在哪，元素就在哪 |
| 字符串字面量 | 存在代码段（常量区），数组是拷贝，指针是指向 |
| `malloc` | 不初始化，返回 `void*`，失败返回 `NULL` |
| `calloc` | 申请 `n * size` 字节并清零 |
| `realloc` | 可能原地扩展或搬迁；失败返回 `NULL` 且原块有效；用临时指针接收 |
| `free` | 只能释放 malloc 系申请的空间；`free(NULL)` 安全；释放后置空 |
| `new/delete` | 操作符；申请单个对象，可以初始化；失败抛 `bad_alloc` |
| `new[]/delete[]` | 申请连续空间，必须与 `delete[]` 配对 |
| `operator new/delete` | 全局函数；`operator new` 底层是 `malloc`，`operator delete` 底层是 `free` |
| `new` 自定义类型 | 申请空间 + 构造；`delete` 析构 + 释放；`malloc/free` 都不调用 |
| `delete[]` 与 N | 有析构函数时编译器会额外保存元素个数，所以不能与 `delete` 混用 |
| 定位 new | 在已有空间上调用构造函数，不申请内存；必须显式析构，原始空间按其来源释放 |
| 常见错误 | `new[]/delete` 混用、跨系统释放、重复释放、忘记释放导致泄漏 |
