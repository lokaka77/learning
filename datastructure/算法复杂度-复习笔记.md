## 1. 数据结构前言

### 1.1 数据结构

**数据结构**是计算机存储、组织数据的方式，是相互之间存在一种或多种特定关系的数据元素的集合。

重点不是背定义，而是理解：不同数据结构解决不同问题。

| 数据结构 | 典型特点 | 适合的典型场景 |
| --- | --- | --- |
| 顺序表 | 连续存储、支持随机访问 | 按下标频繁访问 |
| 链表 | 非连续存储、插入删除灵活 | 频繁插入、删除 |
| 栈 | 后进先出 | 括号匹配、函数调用 |
| 队列 | 先进先出 | 层序遍历、任务排队 |
| 二叉树 | 有层次关系 | 搜索、索引、递归结构 |
| 哈希表 | 根据键快速定位 | 快速查找、去重 |

### 1.2 算法

**算法**是定义良好的计算过程，它接收一个或多个输入，产生一个或多个输出。

可以简单记为：

```text
输入 -> 一系列计算步骤 -> 输出
```

同一个问题可以用不同算法解决。评价算法不能只看“能不能得到正确结果”，还要看它在数据规模变大时是否仍然高效。

### 1.3 数据结构和算法的重要性

数据结构和算法是校招笔试、面试的核心考察内容。典型题目包括：

## 2. 算法效率

### 2.1 为什么不能只看“程序能不能运行”

原课件使用“旋转数组”说明算法效率：

- 题目：[LeetCode 189. 轮转数组](https://leetcode.cn/problems/rotate-array/)
- 简单做法：循环 `k` 次，每次把整个数组向后移动一位。

```c
void rotate(int* nums, int numsSize, int k) {
    while(k--)
    {
        int end = nums[numsSize-1];
        for(int i = numsSize - 1;i > 0 ;i--)
        {
            nums[i] = nums[i-1];
        }
        nums[0] = end;
    }
}
```

这段代码思路正确，小数据可能也能通过测试，但数据量较大时容易超时。

设数组长度为 `n`：

- 外层执行 `k` 次。
- 每轮移动需要执行约 `n` 次操作。
- 最坏情况下总操作次数约为 `k * n`。
- 当 `k` 和 `n` 都是 `10^5` 时，操作次数可达到 `10^10` 量级，明显不能接受。

因此必须用“复杂度”描述算法随数据规模增长时的效率变化。

### 2.2 复杂度的概念

算法运行时消耗两类资源：

1. **时间复杂度**：衡量算法运行快慢，描述基本操作的执行次数随输入规模的变化。
2. **空间复杂度**：衡量算法运行所需额外空间，描述额外变量或递归栈帧数量的变化。

早期计算机内存很小，因此非常关注空间；现代环境中通常优先关注时间复杂度，但内存敏感场景仍要控制空间复杂度。

## 3. 时间复杂度

### 3.1 为什么不直接测量运行时间

直接测量运行时间有三个问题：

1. 不同编译器可能生成不同效率的机器指令。
2. 不同机器配置会影响运行速度。
3. 只有程序写好后才能测试，无法在写代码前进行理论评估。

因此时间复杂度使用一个函数 `T(N)`，描述程序执行次数随输入规模 `N` 的变化。

### 3.2 精确执行次数与增长量级

以原课件中的 `Func1` 为例：

```c
void Func1(int N)
{
    int count = 0;
    for (int i = 0; i < N ; ++ i)
    {
        for (int j = 0; j < N ; ++ j)
        {
            ++count;
        }
    }
    for (int k = 0; k < 2 * N ; ++ k)
    {
        ++count;
    }
    int M = 10;
    while (M--)
    {
        ++count;
    }
}
```

`++count` 的执行次数为：

```text
T(N) = N² + 2N + 10
```

代入不同规模：

| N | T(N) |
| --- | --- |
| 10 | 130 |
| 100 | 10210 |
| 1000 | 1002010 |

当 `N` 很大时，`N²` 起决定性作用，`2N` 和 `10` 可以忽略。因此复杂度关注的是**增长量级**，不是精确次数。

### 3.3 大 O 的渐进表示法

大 O 符号描述函数渐进行为。推导规则：

1. 只保留最高阶项。
2. 去掉最高阶项的常数系数。
3. 若只有常数项，则统一记为 `O(1)`。

所以：

```text
T(N) = N² + 2N + 10  ->  O(N²)
```

### 3.4 复杂度快速判断口诀

| 代码模式 | 常见复杂度 |
| --- | --- |
| 常数次操作，与输入规模无关 | `O(1)` |
| 一个循环，每次只推进固定步数 | `O(n)` |
| 两层独立嵌套循环 | `O(n²)` |
| 每次循环使规模减半，或变量翻倍 | `O(log n)` |
| 一个线性循环内套二分 | `O(n log n)` |
| 每次递归只减少一层，共递归 `n` 层 | `O(n)` |
| 每次递归分成两路，直到规模为 1 | `O(2ⁿ)` |

> 这些只是常见判断方法。遇到未知算法时，仍要回到“计算基本操作次数，再取最高增长量级”的原始方法。

### 3.5 时间复杂度计算示例

#### 示例 1：线性循环加常数

```c
void Func2(int N)
{
    int count = 0;
    for (int k = 0; k < 2 * N ; ++ k)
    {
        ++count;
    }
    int M = 10;
    while (M--)
    {
        ++count;
    }
    printf("%d\n", count);
}
```

执行次数：

```text
T(N) = 2N + 10
```

去掉系数 `2` 和常数 `10`，得到：

```text
O(N)
```

**讲解**：即使循环条件是 `2 * N`，系数也不影响增长量级。

#### 示例 2：两个不同规模变量

```c
void Func3(int N, int M)
{
    int count = 0;
    for (int k = 0; k < M; ++ k)
    {
        ++count;
    }
    for (int k = 0; k < N ; ++k)
    {
        ++count;
    }
    printf("%d\n", count);
}
```

执行次数：

```text
T(N, M) = M + N
```

因此：

```text
O(M + N)
```

**讲解**：当两个输入规模都可能很大，且互相独立时，不能简单写成 `O(N)` 或 `O(M)`，要保留两个变量。

#### 示例 3：固定次数循环

```c
void Func4(int N)
{
    int count = 0;
    for (int k = 0; k < 100; ++ k)
    {
        ++count;
    }
    printf("%d\n", count);
}
```

无论 `N` 多大，循环都只执行 100 次，因此：

```text
O(1)
```

**讲解**：`O(1)` 表示“执行次数与输入规模无关”，不代表只执行一次。

#### 示例 4：`strchr` 的最好、平均、最坏情况

```c
const char * strchr ( const char * str, int character)
{
    const char* p_begin = str;
    while (*p_begin != character)
    {
        if (*p_begin == '\0')
            return NULL;
        p_begin++;
    }
    return p_begin;
}
```

| 情况 | 查找位置 | 执行次数 | 复杂度 |
| --- | --- | --- | --- |
| 最好 | 第一个字符 | 1 | `O(1)` |
| 平均 | 中间位置 | 约 `N/2` | `O(N)` |
| 最坏 | 最后一个或不存在 | `N` | `O(N)` |

三种情况的意义：

- 最好情况：最小运行次数，是下界。
- 平均情况：期望运行次数。
- 最坏情况：最大运行次数，是上界。

实际分析中通常关注**最坏情况**，因为它能保证算法在任何输入下的效率上限。

#### 示例 5：冒泡排序

```c
void BubbleSort(int* a, int n)
{
    assert(a);
    for (size_t end = n; end > 0; --end)
    {
        int exchange = 0;
        for (size_t i = 1; i < end; ++i)
        {
            if (a[i-1] > a[i])
            {
                Swap(&a[i-1], &a[i]);
                exchange = 1;
            }
        }
        if (exchange == 0)
            break;
    }
}
```

执行次数：

- 数组已经有序：只执行第一趟比较，约 `N` 次。
- 数组逆序：比较次数为：

```text
(N-1) + (N-2) + ... + 1 = N(N-1)/2
```

因此最坏复杂度：

```text
O(N²)
```

**讲解**：等差数列求和后保留最高阶项 `N²`。`exchange` 标志只能优化最好情况，不能改变最坏复杂度。

#### 示例 6：对数阶

```c
void func5(int n)
{
    int cnt = 1;
    while (cnt < n)
    {
        cnt *= 2;
    }
}
```

`cnt` 的变化为：

```text
1, 2, 4, 8, 16, ...
```

若执行 `x` 次：

```text
2^x = n
x = log₂n
```

因此：

```text
O(log n)
```

**讲解**：变量每次乘以 2，或区间每次减半，都对应对数阶。`log₂n`、`log n`、`lg n` 在复杂度分析中通常可以视为同一量级。

#### 示例 7：线性递归

```c
long long Fac(size_t N)
{
    if(0 == N)
        return 1;
    return Fac(N-1)*N;
}
```

每次递归调用内部执行常数次操作，一共递归约 `N` 层，因此：

```text
O(N)
```

**讲解**：递归时间复杂度通常可以看“递归树的总节点数”。`Fac` 是一条深度为 `N` 的单链，所以是线性阶。

## 4. 空间复杂度

空间复杂度描述算法运行过程中**额外临时开辟的空间**。

注意：

1. 不算程序本身占用的总字节数，而是统计额外变量数量或递归栈帧数量。
2. 函数参数、局部变量所在的普通函数栈帧在编译期已确定，通常不单独计入。
3. 主要关注运行时显式申请的额外空间，例如数组、递归调用产生的栈帧。

### 4.1 空间复杂度计算示例

#### 示例 1：冒泡排序

```c
void BubbleSort(int* a, int n)
{
    assert(a);
    for (size_t end = n; end > 0; --end)
    {
        int exchange = 0;
        for (size_t i = 1; i < end; ++i)
        {
            if (a[i-1] > a[i])
            {
                Swap(&a[i-1], &a[i]);
                exchange = 1;
            }
        }
        if (exchange == 0)
            break;
    }
}
```

排序在原数组上进行，只额外使用 `end`、`i`、`exchange` 等常数个变量，因此：

```text
O(1)
```

**讲解**：这种不依赖输入规模申请额外空间的算法称为原地算法或 `O(1)` 空间算法。

#### 示例 2：阶乘递归

```c
long long Fac(size_t N)
{
    if(N == 0)
        return 1;

    return Fac(N-1)*N;
}
```

递归深度为 `N`，同时最多存在 `N` 个未返回的函数栈帧，因此：

```text
O(N)
```

**讲解**：递归空间复杂度通常看**最大递归深度**，而不是总调用次数。

### 4.2 空间复杂度速查

| 情况 | 常见空间复杂度 |
| --- | --- |
| 只使用常数个临时变量 | `O(1)` |
| 申请长度与输入规模相关的辅助数组 | `O(n)` |
| 递归最大深度为 `n` | `O(n)` |
| 递归最大深度为 `log n` | `O(log n)` |

## 5. 常见复杂度对比

从小到大：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
```

| 复杂度 | 名称 | 典型示例 |
| --- | --- | --- |
| `O(1)` | 常数阶 | 按下标访问数组 |
| `O(log n)` | 对数阶 | 二分查找 |
| `O(n)` | 线性阶 | 顺序遍历数组 |
| `O(n log n)` | 线性对数阶 | 归并排序、快速排序平均情况 |
| `O(n²)` | 平方阶 | 冒泡排序最坏情况 |
| `O(2ⁿ)` | 指数阶 | 简单递归求解部分组合问题 |
| `O(n!)` | 阶乘阶 | 朴素全排列枚举 |

原课件的增长函数值表：

| n | log₂n | n×log₂n | n² | n³ | 2ⁿ | n! |
| --- | --- | --- | --- | --- | --- | --- |
| 4 | 2 | 8 | 16 | 64 | 16 | 24 |
| 8 | 3 | 24 | 64 | 512 | 256 | 80320 |
| 10 | 3.32 | 33.2 | 100 | 1000 | 1024 | 3628800 |
| 16 | 4 | 64 | 256 | 4096 | 65536 | 2.1×10¹³ |
| 32 | 5 | 160 | 1024 | 32768 | 4.3×10⁹ | 2.6×10³⁵ |
| 128 | 7 | 896 | 16384 | 2097152 | 3.4×10³⁸ | 极大 |
| 1024 | 10 | 10240 | 1048576 | 1.07×10⁹ | 极大 | 极大 |
| 10000 | 13.29 | 132877 | 10⁸ | 10¹² | 极大 | 极大 |

**如何读这张表**：

- 对数阶增长最慢，适合处理很大规模的数据。
- 线性阶、线性对数阶是大多数高效算法追求的范围。
- 指数阶和阶乘阶即使 `n` 只有几十，也往往已经不可接受。

## 6. 复杂度算法题

### 6.1 旋转数组

题目：[LeetCode 189. 轮转数组](https://leetcode.cn/problems/rotate-array/)

题目要求：将数组中的元素向右轮转 `k` 个位置。

例如：

```text
输入：nums = [1,2,3,4,5,6,7], k = 3
输出：[5,6,7,1,2,3,4]
```

#### 思路 1：循环移动

```c
void rotate(int* nums, int numsSize, int k) {
    while(k--)
    {
        int end = nums[numsSize-1];
        for(int i = numsSize - 1;i > 0 ;i--)
        {
            nums[i] = nums[i-1];
        }
        nums[0] = end;
    }
}
```

时间复杂度：

```text
O(n²)
```

空间复杂度：

```text
O(1)
```

**讲解**：

- 每次把最后一个元素保存起来。
- 再将前面所有元素向后移动一位。
- 最后把保存的元素放到第一个位置。
- 外层最多执行 `k` 次，每轮移动约 `n` 次，最坏情况是 `O(n²)`。
- 该代码没有处理 `k >= n` 时的取模，容易执行大量无用移动，因此大数据会超时。

#### 思路 2：辅助数组

```c
void rotate(int* nums, int numsSize, int k)
{
    int newArr[numsSize];
    for (int i = 0; i < numsSize; ++i)
    {
        newArr[(i + k) % numsSize] = nums[i];
    }
    for (int i = 0; i < numsSize; ++i)
    {
        nums[i] = newArr[i];
    }
}
```

时间复杂度：

```text
O(n)
```

空间复杂度：

```text
O(n)
```

**讲解**：

- 轮转后的目标下标是 `(i + k) % numsSize`。
- 两个循环都是线性扫描，所以时间是 `O(n)`。
- 新数组的大小与 `n` 成正比，所以空间是 `O(n)`。
- 这是用空间换时间的典型思路。

#### 思路 3：三次逆置

```c
void reverse(int* nums,int begin,int end)
{
    while(begin<end){
        int tmp = nums[begin];
        nums[begin] = nums[end];
        nums[end] = tmp;
        begin++;
        end--;
    }
}

void rotate(int* nums, int numsSize, int k)
{
    k = k%numsSize;
    reverse(nums,0,numsSize-k-1);
    reverse(nums,numsSize-k,numsSize-1);
    reverse(nums,0,numsSize-1);
}
```

时间复杂度：

```text
O(n)
```

空间复杂度：

```text
O(1)
```

**讲解**：

以 `[1,2,3,4,5,6,7]`、`k = 3` 为例：

```text
第一步：逆置前 n-k 个：[4,3,2,1,5,6,7]
第二步：逆置后 k 个：[4,3,2,1,7,6,5]
第三步：整体逆置：[5,6,7,1,2,3,4]
```

每一步都只交换一次首尾元素，因此总时间是线性阶，并且没有申请辅助数组。

**边界处理建议**：

- 先执行 `k %= numsSize`，避免重复轮转。
- 若 `numsSize == 0` 或 `k == 0`，可直接返回。
- 在原课件代码基础上补充后如下：

```c
void rotate(int* nums, int numsSize, int k) {
    if (numsSize == 0 || k == 0) {
        return;
    }
    k %= numsSize;
    reverse(nums, 0, numsSize - k - 1);
    reverse(nums, numsSize - k, numsSize - 1);
    reverse(nums, 0, numsSize - 1);
}
```

#### [补充例题·力扣] 704. 二分查找

出处：[LeetCode 704. 二分查找](https://leetcode.cn/problems/binary-search/)

题目：给定升序数组 `nums` 和目标值 `target`，返回 `target` 的下标；不存在则返回 `-1`。

```c
int search(int* nums, int numsSize, int target) {
    int left = 0;
    int right = numsSize - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            return mid;
        } else if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }

    return -1;
}
```

复杂度：

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

**讲解**：

1. 每次比较中点 `nums[mid]`。
2. 如果中点小于目标，说明目标只可能在右半部分，移动左边界。
3. 如果中点大于目标，说明目标只可能在左半部分，移动右边界。
4. 每轮搜索区间长度减半，最多执行约 `log₂n` 次。

注意 `mid = left + (right - left) / 2` 可以避免 `left + right` 溢出。

#### [补充例题·力扣] 283. 移动零

出处：[LeetCode 283. 移动零](https://leetcode.cn/problems/move-zeroes/)

题目：将数组中的所有 `0` 移动到末尾，同时保持非零元素的相对顺序。

```c
void moveZeroes(int* nums, int numsSize) {
    int write = 0;

    for (int read = 0; read < numsSize; ++read) {
        if (nums[read] != 0) {
            nums[write] = nums[read];
            write++;
        }
    }

    while (write < numsSize) {
        nums[write] = 0;
        write++;
    }
}
```

复杂度：

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

**讲解**：

- `read` 扫描整个数组，`write` 指向下一个非零元素应该写入的位置。
- 第一次扫描把非零元素按原顺序紧凑到数组前部。
- 第二次扫描把剩余位置全部填成 `0`。
- 每个下标最多被处理常数次，所以总时间是线性阶。

#### [补充例题·牛客] BM17 二分查找-I

出处：[牛客 BM17 二分查找-I](https://www.nowcoder.com/practice/d3df40bd23594118b57554129cadf47b)

题目：在无重复数字的升序数组中找到目标值，存在则返回下标，不存在返回 `-1`。

```c
int search(int* nums, int numsLen, int target) {
    int left = 0;
    int right = numsLen - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            return mid;
        }
        if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }

    return -1;
}
```

复杂度：

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

**讲解**：与力扣 704 思路一致。牛客版的函数参数名可能略有差异，核心仍然是维护 `[left, right]` 闭区间并每次排除一半元素。

#### [补充例题·牛客] BM18 二维数组中的查找

出处：[牛客 BM18 二维数组中的查找](https://www.nowcoder.com/practice/abc3fe2ce8e146608e868a70efebf62e)

题目：在一个每行、每列都递增的二维数组中判断目标值是否存在。

一种适合该矩阵结构的解法是从右上角开始搜索：

```c
#include <stdbool.h>

bool Find(int target, int** array, int arrayRowLen, int* arrayColLen) {
    if (arrayRowLen == 0 || arrayColLen == NULL || arrayColLen[0] == 0) {
        return false;
    }

    int row = 0;
    int col = arrayColLen[0] - 1;

    while (row < arrayRowLen && col >= 0) {
        if (array[row][col] == target) {
            return true;
        }
        if (array[row][col] > target) {
            col--;
        } else {
            row++;
        }
    }

    return false;
}
```

复杂度：

- 时间复杂度：`O(m + n)`，其中 `m` 为行数，`n` 为列数。
- 空间复杂度：`O(1)`。

**讲解**：

1. 从右上角出发，左上方向元素更小，向下方向元素更大。
2. 当前元素大于目标时，当前列右侧不可能出现目标，因此左移一列。
3. 当前元素小于目标时，当前行左侧不可能出现目标，因此下移一行。
4. 每一步都会排除一整行或一整列，最多走 `m + n` 步。

### 6.4 本章复习速查

| 项目 | 结论 |
| --- | --- |
| 时间复杂度关注什么 | 基本操作执行次数随输入规模的增长量级 |
| 大 O 推导 | 留最高阶、去系数、常数写 `O(1)` |
| 对数阶特征 | 每次翻倍或减半 |
| 平方阶特征 | 两层嵌套线性循环 |
| 递归时间复杂度 | 通常看递归树总节点数 |
| 递归空间复杂度 | 通常看最大递归深度 |
| 一般重点 | 最坏时间复杂度 |

复习时最重要的不是记住单个答案，而是能对任意代码完成三步：

1. 数出基本操作执行次数。
2. 写出精确表达式或递推关系。
3. 保留增长最快的一项，得到大 O 表示。
